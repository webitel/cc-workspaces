> ## Not a channel
>
> A video call **follows the logic of a regular call**: it goes through a Flow
> schema and contact-centre queues, and reaches the agent as an ordinary inbound
> call. It is not a fourth activity type alongside calls, chats and tasks.
>
> This file is therefore a **sub-mode of [`../call/`](../call/)**, not a sibling
> of it. Everything in `../call/spec.md` applies unless stated otherwise here.

## 1. Scope

Available during a video call:

- video between agent and client
- **chat** during the call, including file transfer
- **screenshot capture** by the agent
- **recording** — manual by the agent, or automatic
- **client rating** after the call
- review in **History**: recording, screenshots, chat, files

**Desktop only.** Opening the link on mobile shows:
*"This page is not available on mobile. Please switch to desktop"*.

## 2. Client side

### 2.1. Joining

The agent sends the client a link. The link is generated by the system's
`createMeeting` component and has a **limited validity** set by `expireSec`.

On opening the link the client sees a camera/microphone access check page, then
the connection page once the browser permissions are granted.

Connection page controls: microphone toggle, camera toggle, settings, **Join now**.

Settings panel: microphone select, speaker select, **CHECK** (test the speaker),
camera select with preview, close.

### 2.2. During the call

Client interface: agent's video (main), own video (preview), microphone toggle,
camera toggle, settings, chat, end call.

Device settings can be changed mid-call and apply **immediately**.

Client chat supports text, emoji and files.

### 2.3. After the call

The client is taken to a rating screen with two options: **Good** / **Bad**.
After selecting, a confirmation is shown.

The rating is stored in the **`meeting_satisfaction`** variable on the call card,
visible in History → Call info → Variables.

## 3. Agent side (Workspace)

### 3.1. Receiving

The incoming video call appears in the **central panel** and the **Active calls**
block, showing the client's name and the call type. The agent can accept or
reject it — the same affordances as any inbound call.

### 3.2. Three window sizes

After accepting, a video **mini-window** opens. Three modes:

| Mode | Available actions |
| --- | --- |
| **Mini** | expand to full screen, expand to medium, screenshot, start recording |
| **Medium** | screenshot, start recording, expand to full screen, return to mini |
| **Full screen** | screenshot, start recording, return to mini, return to medium |

The client's video occupies the entire screen in full-screen mode.

### 3.3. Chat during a video call

The chat is shown in the central part of Workspace.

> **The chat opens automatically after the client's first message. Until the
> first message arrives, the chat is unavailable to the agent.**

Chat controls: text input, file attachment, emoji, send — plus three call
controls placed in the same bar: **camera** toggle, **hold**, **microphone**
toggle.

### 3.4. Screenshots

The agent captures screenshots of the client's image during the call. They are
listed on the **Screenshots** tab, each with name, date and time.

Per-screenshot actions: **download**, **delete**, **view**.

The viewer offers: previous / next, a thumbnail gallery that can be opened and
closed, download, delete, and open full size.

### 3.5. Ending

The agent presses end call; the connection terminates and the video call closes
in Workspace.

## 4. History

### 4.1. Call card

Standard call list fields: date/time, direction, user, total duration, talk
duration, end reason.

**Call info → Variables** shows `meeting_satisfaction` — the client's rating.

### 4.2. Video Call Recording tab

- view / download / delete the recording (automatic and manual)
- view the chat history
- view / download / delete screenshots captured during the call
- **generate a PDF from the screenshots**
- view / download / delete generated PDFs

### 4.3. PDFs

Registry columns: file name, generation status, creation date/time, creating
user.

Actions: refresh the registry to poll generation status, bulk delete, download,
delete.
